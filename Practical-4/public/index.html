🎓 Key Analysis & Viva Questions (Practical 4)

1. Why must the error handling middleware be defined last in the middleware chain?

Express executes middleware sequentially in the order registered via app.use(). If the error handler were defined before routes, an error thrown by a downstream route would have already bypassed it. Defining it last ensures that whenever a route or middleware invokes next(err), Express skips all subsequent regular middleware and delegates straight to the 4-argument error handler.

2. What is the difference between app.use() and a route-specific middleware?

app.use() mounts middleware globally across every incoming request (or all requests matching a base path prefix, such as /tasks). Route-specific middleware is passed directly as arguments to a specific route definition (e.g. router.get('/:id', validateTaskId, controller)), executing only for that exact endpoint.

3. Why is it considered bad practice to send raw error stack traces to the client?

Raw stack traces expose internal implementation details—such as server directory paths, database table names, installed package versions, and sensitive environment metadata. Attackers can exploit this information disclosure to execute targeted vulnerabilities. In production, stack traces must be logged privately server-side, while clients receive safe, structured JSON error codes.
