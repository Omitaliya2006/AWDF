🎓 Key Analysis & Viva Questions (Practical 5)

1. What is the purpose of a schema in a NoSQL database like MongoDB?

While MongoDB engine itself is schema-less (allowing flexible documents of any shape within the same collection), production web applications require data consistency, predictable payloads, and guaranteed attributes. Mongoose sits as an ODM layer above MongoDB to enforce business rules, type casting, required fields, and default values at the application level before data reaches the database.

2. Why define required fields and default values at schema level vs frontend alone?

Frontend validation is easily bypassed by direct API calls (e.g. via Postman, curl, or mobile clients) or compromised scripts. Schema-level validation guarantees data integrity as the single source of truth regardless of which client dispatched the request, preventing corrupted, partial, or orphaned records from being persisted.

3. What happens internally when a document fails Mongoose validation?

Mongoose executes its validation lifecycle during document instantiation or before the save() operation executes. If any constraint fails, Mongoose halts execution, creates a ValidationError object containing detailed sub-errors for each invalid field, and rejects the Promise before any write network packet is transmitted to the MongoDB daemon.
